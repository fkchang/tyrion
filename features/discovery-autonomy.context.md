# Discovery Autonomy — context

## Why this epic exists

The user observed a specific behavior in a different project (stream_weaver, using the
`beads` issue tracker): more than once, when they asked for a feature, the agent said
"that's already filed" — beads had autonomously tracked the gap earlier, mid-task,
without being asked. The user wanted the same capability in Tyrion, explicitly
identifying it as "very trilaws compliant" (Matt's Law / Forrest's Law / Gloria's Law).

## How beads actually does it (investigated directly in stream_weaver)

Two layers, both auto-generated by `bd init` — no MCP tool involved:

1. A `SessionStart`/`PreCompact` hook runs `bd prime`, re-injecting ~110 lines of
   workflow rules + recent "memories" into context every session and every compaction.
2. Instruction text in that injected output tells the agent to file issues for
   anything needing follow-up — explicitly biased toward over-filing: *"Persistence
   you don't need beats lost context."*

Filing itself is one non-interactive command, no confirmation — genuinely zero-friction
(strong Forrest's Law). But two real costs showed up in the live data (162 issues, 51
open in that project):

- **Digest strain** (Matt's Law failure) — no web UI at all; `bd ready` truncates at 10
  of 46; past-human-scanning at that volume.
- **Provenance is erased** (Gloria's Law failure) — every issue's `created_by` defaults
  to `git user.name`, so agent-filed and human-filed are indistinguishable. 51 open
  issues the user didn't personally decide to track, with no way to bulk-triage "mine"
  vs. "the agent noticed this" — a classic guilt-inbox, the ADHD tool-death Gloria's Law
  warns about.

This epic's design (search-before-file, 3-mark/story budget, actor/origin tagging,
`discovery defer` as a real exit) exists specifically to avoid beads' two failure modes
while keeping its one genuine win: the agent files without being asked, mid-task, at
zero cost to the human in that moment.

## Why no new hook

`tyrion prime` is already wired to `SessionStart` and `PreCompact` via
`tyrion_hook_groups` (`lib/tyrion/commands.rb:3241-3247`) — this is structurally
identical to how beads' `bd prime` hook works, just already built. The autonomy nudge
rides that existing mechanism (two added lines of output) rather than introducing any
new hook. A PostToolUse hook that pattern-matches Edit/Write diffs for TODO/FIXME and
auto-files was explicitly considered and rejected: "worth tracking" is a judgment call,
not a regex; it would fire on TODOs written deliberately as part of the story; and a
hook can't fail open the way a claim-gate can — every false positive becomes permanent
ledger state a human has to clean up. `lib/tyrion/lesson_miner.rb` already established
the precedent for this call: it "never writes anything itself," producing candidates
for a human approval loop instead.

## Why the instruction lives in the skill, not a global CLAUDE.md

A global `~/.claude/CLAUDE.md` standing instruction was considered and rejected:
unconditional, it would fire in every repo including ones with no Tyrion project (where
`tyrion mark` just errors "No active project"), and CLAUDE.md isn't hook-reinjected on
`/clear` the way `tyrion prime` is — so it decays exactly when it's needed most. The
behavioral instruction belongs scoped to a real project with a real in-progress story,
i.e. `skills/tyrion-implement/SKILL.md`.

## Ambient page — why not a herdr plugin

Investigated directly (herdr 0.8.0, via Codex): herdr's own docs state "native
non-terminal plugin panes are a later surface." Its plugin API is real (manifest +
out-of-process command; pane placements `overlay/split/tab/zoomed/popup`) but every
pane is PTY-backed terminal — no webview, DOM, or URL-embedding capability exists today.
Two things herdr does offer, deliberately out of scope for this epic but worth revisiting
later:

- `herdr pane report-metadata --token NAME=VALUE` — can publish short strings (e.g.
  `$unread_marks=3`) into existing sidebar rows; requires user config to wire the token
  into a row, not a rich widget.
- `herdr notification show` — toast/OS notifications, good for threshold-crossing
  alerts, not continuous ambient state (also currently disabled in the user's config:
  `[ui.toast] delivery = "off"`).

The `/ambient` page is built as a plain browser page for this reason — it works today
in a regular browser split, cmux's embedded browser (`cmux browser open-split`), or
VS Code's Preview pane, with no herdr dependency. A herdr-specific adapter (sidebar
token poller, or a notification bridge) layered on top of the same JSON endpoint is a
legitimate future addition, not part of this epic.

## Rejected alternatives (ambient page)

- Reusing the existing `/discoveries` page in a narrow pane — rejected: that page is
  built for triage/reading (Matt's Law "digest"), with full navbar/sidebar chrome that
  wastes width in a narrow pane and creates visual noise incompatible with an ambient,
  glance-only surface.
- SSE/WebSocket push instead of polling — rejected: nothing else in the codebase uses
  either; the existing `/api/poll` token-diff pattern is proven and dependency-free, and
  60s polling latency is fine for something explicitly non-urgent.

## Vetting pass (Codex, before import) — corrections made

The initial draft was vetted against the actual codebase (not just design intent) before
import. Real blockers surfaced and were fixed in the .feature file:

- **Wrapped criteria were silently truncated.** The importer (`lib/tyrion/importer.rb`)
  only recognizes physical lines starting with a Gherkin keyword — it does not join
  indented continuations. Every criterion is now one physical line.
- **Epic-level intent was being dropped.** Only a `# Intent:` comment block (with
  contiguous `#`-prefixed continuation lines) is captured for `feature_description`;
  plain prose under `Feature:` and a `Background:` block are both silently ignored.
  The epic intent now lives in a `# Intent:` comment; the old `Background:` block was
  removed since its content duplicates this context.md, which is loaded into
  `epics.context_md` directly.
- **`mark-provenance` was going to overload a column promotion already uses.**
  `promote_discovery_to_story` overwrites `discoveries.story_id` with the *destination*
  story. Filing provenance now lives in a new, separate `source_story_id` column, set
  once at creation and never touched by promotion.
- **`discovery-actor-origin`'s classification rule was a guessable heuristic.**
  "Active story present → agent" misclassifies a human running commands during an
  active story. Replaced with an explicit `--auto` flag on `tyrion mark`/`tyrion
  discover` (and `tyrion spike start/done` for consistency) — the skill instruction
  text tells the agent to always pass it, so classification is exact, not inferred.
- **The 3-mark budget and re-sighting note had no real command behind them.**
  `tyrion mark`'s confirmation line now reports the running per-story count (via
  `source_story_id`) so an agent can self-enforce the budget without querying SQLite;
  the re-sighting instruction now cites the actual existing command
  (`tyrion note <slug> observation "..."`).
- **`discover-noninteractive-flags` had the mark/findings_ready UI chip backwards.**
  `tyrion discover disc-NNN` renders on **mark** rows, not findings_ready rows.
  Redesigned around what that chip actually implies: upgrading an existing mark to
  findings_ready, not creating an unrelated new discovery.
- **`discovery-defer-command` needed a reason column and validated source states,**
  not just a status flip — added `defer_reason`, restricted to `mark`/`findings_ready`
  source states, defined not-found and repeat-defer behavior.
- **`shape-skill-discovery-recall-check` violated `/tyrion-shape`'s own "never write
  the DB before approval" rule** by having the skill call `discovery defer` during
  drafting. Fixed: shape only surfaces and folds-in or calls out overlapping
  discoveries in the reviewable draft; deferring remains a manual human action,
  always.
- **`ambient-poll-endpoint`'s update contract was internally inconsistent.** The token
  covered the findings_ready count but the spec only patched the marks list; a mark
  aging past 14 days changes visually without its content/token changing at all.
  Fixed: the endpoint returns full data (not just a token) and patches both sections
  together; the client recomputes each mark's aging color from its own timestamp on
  every poll tick, independent of token-diffing.
- **`web-ambient-command` didn't pin project scope**, risking an already-running
  server (started for a different project) silently showing the wrong marks. Fixed:
  it always opens the fully-scoped `/ambient?project=<slug>` URL.
- **CLAUDE.md's existing Discovery layer docs are already wrong** (says disc-NNN is a
  per-project counter; `create_discovery`'s own comment says it's deliberately
  global) — folded that correction into `claude-md-discovery-docs`.
- **No dependency graph across the 15 stories**, which matters if this epic is ever
  orchestrated in parallel waves. Encoded via `tyrion depends add` after import (see
  below), not in the .feature file itself — Tyrion has no Gherkin-level dependency
  syntax; `depends_on` is a separate CLI-managed field.
- **RIGOR tags were too uniformly low.** `discovery-search-command`,
  `discovery-actor-origin`, and `ambient-poll-endpoint` moved to `strict` (each has a
  way to be subtly wrong that only a test would catch); `mark-provenance` and
  `prime-marks-nudge` moved from `trivial` to `loose`.

Story dependency graph applied post-import via `tyrion depends add <slug> <dep-slug>`:

- `mark-provenance`, `discover-noninteractive-flags` depend on `discovery-actor-origin`
  (the `--auto` flag and origin column need to exist first)
- `implement-skill-continuous-capture-guardrails` depends on `discovery-search-command`
  and `discover-noninteractive-flags` (the skill text cites both commands)
- `shape-skill-discovery-recall-check` depends on `discovery-defer-command`
- `status-marks-text` depends on `discovery-search-command` (the marks alias fix)
- `ambient-poll-endpoint`, `web-ambient-command` depend on `ambient-route-and-view`
- `claude-md-discovery-docs` depends on `discovery-actor-origin` and
  `discovery-defer-command` (it documents both)

## Deferred out of this epic

- Any herdr-specific plugin/pane/notification integration (see above).
- FTS5 full-text search for discoveries — LIKE is sufficient at current volume (tens to
  low hundreds of rows per project); FTS5 is the upgrade path only past roughly 1000
  discoveries, and would add a shadow table + sync triggers this epic doesn't need yet.
- Surfacing open discoveries automatically during `tyrion import` via fuzzy-matching
  against new epic slugs — considered and dropped: wrong moment (import is deterministic
  and idempotent; fuzzy matches would muddy that), and it duplicates what
  `discovery search` already does on demand. The `/tyrion-shape` recall check captures
  the same value at the right moment, deterministically.
